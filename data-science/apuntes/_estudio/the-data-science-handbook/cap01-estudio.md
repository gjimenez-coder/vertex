# Introduction: Becoming a Unicorn (Introducción: Convertirse en un unicornio) — Estudio

## Tarjetas de repaso

P: ¿Cómo define Cady el data science?
R: Trabajo analítico que, por un motivo u otro, exige una cantidad sustancial de habilidades de ingeniería de software.

P: ¿Qué es un "unicornio" en este contexto?
R: La persona capaz de construir buenos modelos estadísticos, programar software de calidad y conectar todo con problemas de negocio; es tan rara que los reclutadores la llaman así.

P: Según el autor, ¿por qué los unicornios son raros?
R: Por un accidente histórico: pocos programas educativos enseñan todas esas destrezas, no porque una sola persona no pueda dominarlas.

P: ¿Qué requiere alcanzar el entregable que a veces podría dar un estadístico o analista?
R: Destrezas de software que un analista típico no tiene: computación distribuida por datos muy grandes, parsing de formatos enrevesados o software de producción en tiempo real.

P: ¿Qué frase de Nate Silver recoge el capítulo sobre el data scientist?
R: "I think data scientist is a sexed-up term for statistician"; Cady admite que tiene parte de razón, pero solo parte.

P: ¿En qué se diferencia el trabajo del data scientist del de la estadística?
R: La estadística se ocupa de métodos matemáticos rigurosos para problemas bien definidos; el data scientist pasa la mayor parte del tiempo llevando los datos a una forma donde esos métodos puedan aplicarse.

P: ¿De qué tipo de datos nació el data science?
R: De datos no estructurados que las herramientas estadísticas ignoraban: páginas HTML, imágenes, correos y logs crudos de servidores web.

P: ¿Qué predice Cady para dentro de 20 años?
R: Que estadística, data science y machine learning se fundirán en una sola disciplina, porque sus diferencias son de grado o de accidente histórico.

P: ¿Cuáles son las tres secciones del libro?
R: The Stuff You'll Always Use, Stuff You Still Need to Know y Stuff That's Good to Know.

P: ¿Cuáles son los tres modos de uso del libro?
R: Leerlo de principio a fin como curso autocontenido, usarlo para ponerse al día en un tema concreto, y aprovechar su código de ejemplo reutilizable.

P: ¿Por qué todo el código está en Python?
R: Para usar un solo lenguaje en todos los ejemplos y mantener el libro legible; además es el más popular entre data scientists y, según el autor, el mejor "segundo mejor" lenguaje para proyectos multidisciplinares.

P: ¿Qué consejo da el autor sobre el dominio de lenguajes?
R: Es mucho mejor dominar un lenguaje hasta producir código fiable y de calidad que ser mediocre en varios.

P: ¿En qué dos formas vienen los datos de ejemplo del libro?
R: Datasets de prueba incluidos en las librerías científicas de Python, y datos extraídos de Internet (fuentes como Yahoo y Wikipedia) con scripts que incluyen el código de descarga.

## Preguntas de autoevaluación

P: ¿Por qué la estadística juega un papel secundario en el trabajo de data science?
R: Porque el grueso de la tarea es preparar los datos, extraer features significativas y encajar el problema analítico con los objetivos de negocio; solo después se aplican las herramientas estadísticas, y muchas veces ni siquiera hacen falta. (Sección "¿Acaso los data scientists no son solo estadísticos sobrepagados?")

P: ¿Qué utilidad tiene la Parte I para quien no aspira a ser data scientist completo?
R: Para quien solo necesita data science para responder una pregunta concreta, la Parte I (The Stuff You'll Always Use) probablemente baste, pues cubre las habilidades core indispensables. (Sección "¿Cómo está organizado este libro?")

P: ¿Qué diferencia a las habilidades de la segunda sección entre sí?
R: Algunas, como clustering, son tan comunes que casi entran en la primera sección; otras, como el procesamiento de lenguaje natural, son especializadas: críticas en ciertos dominios y superfluas en otros. (Sección "¿Cómo está organizado este libro?")

P: ¿Por qué el libro no pretende ser exhaustivo?
R: Porque el campo es demasiado grande y cambia demasiado rápido; busca dar una base sólida del panorama general y un conjunto de habilidades "completo" para salir a trabajar. (Sección "Lo que necesitas saber")

P: ¿En qué casos no sería Python la mejor opción según el autor?
R: Si solo necesitas estadística, cálculo numérico o parsing web hay opciones mejores; Python destaca cuando debes hacer todo eso dentro de un mismo proyecto multidisciplinar. (Sección "¿Por qué todo está en Python?")

P: ¿Por qué el libro incluye bloques de código bastante largos?
R: Porque como data scientist necesitas saber leer piezas largas de código —habilidad no opcional— y para facilitar que reutilices el código del libro, liberado al dominio público en GitHub. (Sección "Código de ejemplo y datasets")

P: ¿Qué quiere transmitir el autor además de enseñar data science práctico?
R: Lo emocionante de esta disciplina profundamente interdisciplinar, e invita a escribirle con comentarios o erratas. (Sección "Palabras de despedida")
