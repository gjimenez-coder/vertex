# Glosario — Claude Certified Architect – Foundations (CCA-F)

- **Access failure**: error de acceso; se distingue de un valid empty result y devolver vacío ante un fallo de acceso es el anti-patrón más peligroso (dominio2, tarea 2.2)
- **AgentDefinition**: definición de subagent con description, prompt y restricción de herramientas, usada al invocar subagents (dominio1, tarea 1.3)
- **Agentic loop**: control de flujo determinista en código que se repite mientras `stop_reason` sea `"tool_use"` y termina con `"end_turn"` (dominio1, tarea 1.1)
- **allowedTools**: lista de herramientas permitidas a un agente; debe incluir "Task" (hoy Agent) para invocar subagents y sirve para dar a cada agente solo lo que su rol necesita (dominio1, tarea 1.3)
- **Attention dilution**: pérdida de calidad al revisar mucho de una vez; se resuelve con pases locales más un pase de integración (dominio1, tarea 1.6)
- **Case facts block (persistent)**: bloque de hechos del caso incluido en cada prompt, fuera del historial resumido y reinyectado tras la compaction, para no perder importes, fechas e identificadores (dominio5, tarea 5.1)
- **Claim-source mapping**: vínculo entre cada afirmación de una síntesis y su fuente, que conserva la atribución en cada handoff junto con la publication date (dominio5, tarea 5.6)
- **CLAUDE.md**: archivo de instrucciones persistentes, de carácter advisory; lo que debe cumplirse siempre va en hooks o `permissions.deny` (dominio3, tarea 3.1)
- **`context: fork`**: opción de una skill que aísla su salida verbosa en un sub-agent (dominio3, tarea 3.2)
- **Context rot**: pérdida de fiabilidad a medida que la ventana de contexto se llena, antes de que se agote (dominio5, tarea 5.1)
- **Coordinator**: agente del patrón hub-and-spoke que decide qué trabajo existe, particiona el alcance, agrega resultados y responde por la salida final (dominio1, tarea 1.2)
- **Coverage honesty**: anotar qué se completó, qué no y por qué, porque un resultado parcial honesto vale más que uno que parece completo (dominio5, tarea 5.3)
- **`custom_id`**: identificador con el que se casan los resultados de la Message Batches API (dominio4, tarea 4.5)
- **Direct execution**: modo para cambios acotados y conocidos, frente a plan mode (dominio3, tarea 3.4)
- **Dynamic adaptive decomposition**: descomposición dinámica de tareas para alcance desconocido, frente al pipeline fijo de prompt chaining (dominio1, tarea 1.6)
- **`end_turn`**: valor de `stop_reason` con el que termina el agentic loop; es la señal autoritativa de fin (dominio1, tarea 1.1)
- **Explore subagent**: subagent que mantiene la exploración verbosa fuera de la conversación principal (dominio3, tarea 3.4)
- **Few-shot prompting**: técnica con 2 a 4 ejemplos diversos, con razonamiento, en `<example>`; la más eficaz para formato inconsistente y casos ambiguos (dominio4, tarea 4.2)
- **Flag `-p`**: opción de Claude Code en CI/CD que evita que el job se cuelgue (dominio3, tarea 3.6)
- **Forced selection**: modo de `tool_choice` (`{"type": "tool", "name": ...}`) que garantiza una herramienta concreta (dominio2, tarea 2.3)
- **fork_session**: crea ramas divergentes desde una base compartida (dominio1, tarea 1.7)
- **Glob**: herramienta integrada que busca rutas, frente a Grep que busca contenido (dominio2, tarea 2.5)
- **Grep**: herramienta integrada que busca contenido (dominio2, tarea 2.5)
- **Handoff estructurado**: traspaso a un humano con resumen autocontenido, con customer ID y recommended action entre sus campos, porque el humano no ve la transcripción (dominio1, tarea 1.4)
- **Hooks**: mecanismos deterministas del Agent SDK para interceptar llamadas a herramientas (PreToolUse y PostToolUse) y aplicar enforcement (dominio1, tarea 1.5)
- **Hub-and-spoke**: patrón en el que toda la comunicación pasa por el coordinator, lo que da observabilidad, manejo de errores consistente y flujo de información controlado (dominio1, tarea 1.2)
- **Interview pattern**: técnica de refinamiento iterativo para dominios desconocidos (dominio3, tarea 3.5)
- **isRetryable**: campo del error MCP que solo pregunta si reenviar la misma llamada funcionaría (dominio2, tarea 2.2)
- **Least privilege**: cada agente recibe solo las herramientas que su rol necesita; dar 18 herramientas a un synthesis agent favorece el mal uso (dominio2, tarea 2.3)
- **Lost in the middle**: problema posicional que se mitiga con un resumen de hallazgos clave al principio y cabeceras de sección (dominio5, tarea 5.1)
- **`.mcp.json`**: archivo en la raíz del proyecto, compartido y versionado, para servidores MCP; los secretos se referencian con `${VAR}` (dominio2, tarea 2.4)
- **MCP resources**: catálogos de solo lectura de un servidor MCP que evitan llamadas exploratorias (dominio2, tarea 2.4)
- **`/memory`**: primer paso de diagnóstico cuando las convenciones se siguen de forma inconsistente; muestra qué está cargado, no carga nada (dominio3, tarea 3.1)
- **Message Batches API**: 50% más barata, con ventana de hasta 24 horas sin SLA de latencia y sin multi-turn tool calling; no sirve para flujos bloqueantes (dominio4, tarea 4.5)
- **Misrouting**: enrutado incorrecto de herramientas, que se corrige primero expandiendo y desambiguando las descripciones (dominio2, tarea 2.1)
- **Path-specific rules**: reglas en `.claude/rules/` con frontmatter `paths` y glob patterns que se cargan solo al tocar archivos coincidentes (dominio3, tarea 3.3)
- **`permissions.deny`**: mecanismo determinista al que apunta "Never" cuando algo no debe ocurrir (dominio3, tarea 3.1)
- **Plan mode**: modo para tareas ambiguas, de gran alcance o con varios enfoques; la elección depende de la ambigüedad, no de la dificultad (dominio3, tarea 3.4)
- **PostToolUse**: hook que corre después de la herramienta y sirve para normalizar resultados, no para impedir la acción (dominio1, tarea 1.5)
- **Prerequisite gate**: control programático que exige un paso previo antes de una operación crítica (dominio1, tarea 1.4)
- **PreToolUse**: hook que bloquea o modifica antes de ejecutar (dominio1, tarea 1.5)
- **Programmatic enforcement**: control de lo que Claude puede hacer mediante prerequisite gates y hooks; se espera cuando un fallo implica pérdida financiera, riesgo de seguridad o compliance (dominio1, tarea 1.4)
- **Progressive summarisation**: resumen progresivo que destruye importes, fechas e identificadores (dominio5, tarea 5.1)
- **Prompt chaining**: pipeline fijo de pases enfocados para tareas con aspectos conocidos (dominio1, tarea 1.6)
- **Prompt guidance**: indicación en el prompt de lo que Claude debería hacer; es probabilística (dominio1, tarea 1.4)
- **`--resume`**: continúa una sola sesión con nombre (dominio1, tarea 1.7)
- **Retry-with-error-feedback**: reintento que incluye documento original, extracción fallida y error de validación específico; solo funciona con errores resolubles y con límite de dos a tres reintentos (dominio4, tarea 4.4)
- **Scratchpad file**: archivo de notas de trabajo que resuelve la saturación de contexto en sesiones y exploraciones largas (dominio5, tarea 5.4)
- **Sentiment**: señal poco fiable como trigger de escalación, igual que la confianza autorreportada (dominio5, tarea 5.2)
- **Silent suppression**: anti-pattern de ocultar un fallo; junto con workflow termination debe evitarse (dominio5, tarea 5.3)
- **Skill**: directorio con `SKILL.md` que crea el slash command; se carga bajo demanda cuando se invoca (dominio3, tarea 3.2)
- **State manifest**: archivo que permite recuperar crashes en exploraciones largas de código (dominio5, tarea 5.4)
- **stop_reason**: campo de la respuesta que controla el agentic loop; `"tool_use"` continúa y `"end_turn"` termina (dominio1, tarea 1.1)
- **Stratified sampling**: muestreo estratificado, incluida la salida de alta confianza, para validar la automatización por segmento (dominio5, tarea 5.5)
- **Strict tool use**: elimina errores de sintaxis, no los semánticos, que requieren validación (dominio2, tarea 2.3)
- **Task tool (Agent tool)**: herramienta necesaria en `allowedTools` para invocar subagents; las tareas independientes se lanzan en una sola respuesta para ejecutarlas en paralelo (dominio1, tarea 1.3)
- **tool_choice**: controla cuándo se llama a una herramienta: `auto` permite responder con texto, `any` garantiza una llamada pero no cuál, y forced selection garantiza una concreta (dominio2, tarea 2.3)
- **tool_result**: bloque devuelto en un único mensaje `user`, antes de cualquier texto, con `tool_use_id` que coincide con el bloque `tool_use` (dominio1, tarea 1.1)
- **Tool use con JSON schema**: método más fiable para salida estructurada; elimina errores de sintaxis pero no los semánticos (dominio4, tarea 4.3)
- **Triggers de escalación**: petición explícita, brecha de política, límite de autoridad y fallo repetido (dominio5, tarea 5.2)
